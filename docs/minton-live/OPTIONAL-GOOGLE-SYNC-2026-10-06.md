# 선택적 Google 로그인·기기 이어받기 — 부분 구현, 동시 사용 미완료

> 재검토: 이 후보는 한 기기씩 이어받는 구현이며 두 관리자 기기의 동시 조회·수정을 충족하지 않습니다. 배포 승인 요청을 보류합니다. 최신 판정·추가 설계·승인 준비 범위는 [동시 사용 재검토](CONCURRENT-GOOGLE-SYNC-REVIEW-2026-10-06.md)를 따릅니다. 아래 함수1개 배포안은 이전 좁은 후보의 기록으로, 동시 사용 완성본의 확정 배포 범위가 아닙니다.

사용자 요청: 비회원도 명부·코트·설정·대진을 그대로 만들고 운영한다. 관리자가 Google 로그인을 선택하면 같은 계정의 다른 기기에서 이어 운영한다. 회원 링크와 이름 조회는 로그인 없이 유지한다.

## 구현 범위

- 기준 운영본 v1.10.765, 4ac42d3. 별도 `codex/optional-google-sync-20261005` 작업트리에서 구현. 기존 실험 원본·D자판기·닫힌 Lite 시험 사이트 불변.
- 초기 비회원 앱은 인증 응답을 기다리지 않는다. Google 버튼을 누르고 로그인한 뒤, 현재 기기 자료를 본인 계정에 연결할지 명시 확인한다. 원래 비회원 localStorage는 삭제/이동/덮어쓰기하지 않는다.
- 계정 자료는 UID별 단일 JSON 저장소로 분리한다. 명부, 민턴LIVE/팀전 설정·대진·진행 기록·공유 연결 정보 등 허용 목록만 동기화한다. 회원 식별 캐시와 Firebase 토큰, 기기별 admin grant는 전체 복사하지 않는다. 기존 세션 운영 초대 capability는 관리자 상태에 포함되므로 계정 저장소는 비공개로 취급한다.
- `adminWorkspace` callable은 검증된 Google 인증만 받으며 UID는 인증 토큰에서만 가져온다. `adminWorkspaces/{uid}` 아래 저장하고 현재 루트 deny 규칙을 상속한다. database.rules.json 변경 없음. 최대 1.2MB/150키, 이전 서버 사본 3개, revision 비교 및 operationId 재전송 방지.
- 활성 기기 1대: 45초 임대, 10초 주기 갱신, 변경 후 800ms 저장 시도. 변경이 없으면 명부/대진을 반복 업로드하지 않는다. 다른 기기는 ‘이 기기로 이어하기’로 요청하고, 기존 기기는 진행 중 요청·저장을 정리한 후 권한을 넘긴다. 복제 탭도 Web Locks로 별도 기기 식별자를 배정한다. Web Locks 없는 브라우저는 안전을 위해 새 식별자를 쓰므로 새로고침 뒤 이전 임대 만료 대기가 생길 수 있다.
- 계정 운영 중 연결 실패/임대 만료는 편집을 멈추고 기기 사본을 유지한다. 서버 최신 revision과 충돌하면 자동 덮어쓰기하지 않고 백업/최신 자료 선택 화면을 띄운다. 저장 응답 유실은 영수증으로 복구한다. 로그아웃 시 그 기기의 원래 비회원 자료로 돌아간다.
- 계정이 바뀌면 이전 화면·캐시 접근·백업 내보내기를 즉시 잠근다. SDK 쓰기와 callable 발행도 잠금 후 거절한다. RTDB 연결을 끊어 이전 페이지의 대기 쓰기 재연결을 막는다. 진행 중 요청은 넘김 시 최대 5초 대기하고 응답 확인 실패를 표시한다.
- 팀전은 대진 생성 전 준비 상태도 로그인 연결 시 저장한다. 기존 명부 서버 저장에서 보관한 명부는 계정 메뉴에서 명시적으로 가져오되, 같은 ID의 현재 명부는 보존한다.
- 연결된 밸런스게임 설정 화면도 계정 명부를 사용한다. hash가 있는 설문 참여 링크는 계정 부트스트랩을 우회한다. checkin.html/rsvp.html/view.html의 회원 흐름은 변경하지 않았다.

## 현재 사용상의 제한

두 관리자 기기의 동시 편집/자동 병합은 제공하지 않는다. 한 기기에서 운영하고 다른 기기로 넘겨받는다. 두 번째 관리자 기기는 이어받기 안내를 표시한다. 일반 회원 화면은 기존처럼 실시간 조회한다. 계정 운영은 연결이 필요하며 비회원 사용은 기존 오프라인 동작을 유지한다.

실제 Google 인증, Firebase 배포 후 연동, 실기 iPad Safari/PWA, 실제 연결된 민턴LIVE/팀전에서 경기 명령이 진행 중일 때의 넘김·백그라운드 만료·망 단절은 아직 검증하지 않았다. 합성 경기 상태 복원 통과를 실전 명령/권한 검증 통과로 간주하면 안 된다. 기존 공개 live 경로 권한을 이번 계정 저장 기능이 강화했다고 주장하지 않는다. 새로운 계정 저장 경로만 Google UID로 분리한다.

## 운영 적용 전 승인할 정확한 범위

1. kokmatch-23b31에서 기존 Google 공급자와 `kimminhyun22.github.io` 승인 도메인을 확인하고, 필요한 경우만 활성화/추가. 공급자 지원 이메일 등 새 필수 입력이 없으면 기존 설정 유지. 카카오/네이버/Lite 재개 없음.
2. 새 callable `adminWorkspace` 1개 배포. us-central1, maxInstances 2, 256MiB, timeout 20초. 기존 경기 Functions·DB 규칙·비밀값 배포 없음. 활성 관리자당 기본 갱신 최대 약 360회/시간과 변경 시 저장 호출/DB 전송이 추가된다. 실제 요금·무료 구간 여유는 아직 확인하지 않았으며 신규 유료 시험 승인 전 실제 호출 시험하지 않았다.
3. 승인 후 최신 main 재확인·다음 버전 bump·전체 게이트를 거쳐 정적 배포. 먼저 새 서버 기능을 배포하고 그다음 관리자 UI를 배포한다. 현재 운영본은 v765 그대로다.
4. 실제 Google 로그인은 사용자 본인 인증이 필요하다. 격리 브라우저·가명 데이터로 같은 계정의 두 기기, 로그아웃/계정 전환, 운영 중 경기 명령·망 단절·이어받기를 실배포 검증한다. 기존 사용자 workspace가 있으면 시험으로 덮어쓰지 않는다. 승인된 테스트 자료만 정리한다.

위 실제 연동 검증 전에는 ‘다기기 운영 배포 완료’로 보고하지 않는다. 문제가 있으면 기존 v765 정적 화면으로 되돌리고 비회원 원본/계정 백업을 보존한다.
