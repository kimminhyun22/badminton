# 팀전 신청자 밸런스게임

## 사용자 결정 — 2026-11-11

팀전 신청 명단에 있는 선수끼리 개인 실력을 비교한다. 가대진의 승패를 묻는 퀴즈가 아니다. 기존 클럽의 실력점수에서 출발해 임원이 부족한 비교를 보완하고, 관리자가 보정안을 확인하여 공식 명부에 저장한 뒤 청·홍팀을 배정한다. 참가하지 않는 임원도 평가할 수 있다. 링크를 실제 임원에게 전달하는 것은 운영자가 한다.

## 점수와 신원

- 행사 최초 개인 점수를 고정 기준으로 삼고 이번 행사에서 수집한 새 답변만 계산한다. 과거 답안을 재입력하거나 이미 보정한 점수를 다시 출발점으로 바꾸지 않는다.
- 회원 식별자와 클럽 범위로 대상을 연결한다. 신청자 추가·취소·재참가에도 기존 질문 식별자와 답변을 재번호화하지 않는다. 취소자의 답변은 보관하고 현재 신청자만 출제·계산한다.
- 평가 대상과 평가자를 구분한다. 관리자의 직접 평가도 본인 이름으로 참여하여 같은 사람이 두 종류의 표를 갖지 않게 한다. 자기 자신이 포함된 비교는 제외한다.
- 임원 전용 인증을 새로 도입하는 기능은 아니다. 링크를 아는 사람이 이름을 선택하는 기존 방식이며 임원방에만 공유한다.
- 근거가 충분한 선수만 명부 저장 후보가 된다. 미참가자·평가 부족 선수는 기존 점수를 유지한다. 명부 미등록 참가자는 이번 행사 점수만 적용한다.
- 명부 저장 전 최신 답안, 신청자 구성, 원래 명부 및 이전 자체 저장값을 대조한다. 다른 평가나 수동 수정과 충돌하면 덮어쓰지 않는다. 같은 결과의 재시도는 점수를 누적시키지 않는다.
- 다른 평가에서 최신 점수를 저장한 뒤 과거 평가를 새로고침해도 과거 보정안으로 되돌릴 수 없도록 저장 출처를 검사한다.

## 사용 흐름

1. 팀전 참가자를 등록하고 상단 **팀전 신청자 밸런스게임**을 연다.
2. **단톡방 링크 공유**로 임원방에 전달한다. 임원은 본인 이름을 선택하고 짧은 질문 묶음에 응답한다.
3. 신청자가 바뀌면 같은 입구에서 최신 신청자를 반영한다. 기존 응답은 보존한다. 동일 ID의 이름·급수·성별·연령이 바뀐 경우에는 자동으로 다른 사람으로 처리하지 않고 확인이 필요하다.
4. 관리자가 결과를 보고 **명부에 저장하고 팀전에 적용**을 누른다.
5. 청·홍팀과 대진을 생성한다. 이미 생성한 미진행 대진은 명시적으로 정리해야 하며 진행 중 경기에는 적용하지 않는다.

## 알고리즘·품질 기준표 점검

개인 점수 계산식 comparison-v4, 후보 준비도, 팀 배정·대진 후보 순위 및 품질점수 v10의 배점은 유지한다. 변경은 평가 대상 범위와 점수 저장·인계다. 상대 3명과 급수 연결 조건은 정확도나 객관적 실제 실력의 보장이 아니다. 이번에도 점수 기준표와 데이터 입력 경로를 함께 확인하며, 동일 점수를 입력하면 기존 품질 계산이 같아야 한다. 실제 승패 예측력 개선이나 전역 최적을 검증했다고 표현하지 않는다.

## 검증 상태

배포 전 전체 회귀 196/196·Functions 문법17·실패0(111초), 신규 회귀7개 및 훼손 시험을 통과했다. Astra Ultra가 최신 핵심6회귀를 독립 재실행해 차단 사유 없음을 확인했다.

격리 브라우저 실제 흐름: 신청자7명(등록6+게스트1)→비출전 임원21답안→공식 명부5명 변경/1명 유지·게스트 행사 반영→8경기 생성·새로고침·복원 일치. 320/375/768/1024px 가로 넘침0·페이지 오류0. 이미 대진이 있는 경우 pending만 보관하고 진행 중 적용을 차단했으며,7→6명 동기화는15답안 유효/6답안 보관과 원래 점수 보존을 확인했다. 임시 모의 서버 검사이며 공개 배포 검증과 구분한다.

공식 명부는 유한 실력점수에서 파생한 level이 기존0~10 밖이어도 잘라내지 않고 저장하도록 전달·서버 계약을 맞췄다. 합성8명·3임원 실제 보정→공식 명부 계획→서버 핸들러 저장/조회/재시도/복원 회귀로 검증했다. 원래 개인 점수가 없는 명부와 비유한값 거절은 유지했다.

v805 공개 배포 후 실제 서버에 가명21답안을 저장했으나, RTDB가 마지막 빈 질문 배열을 생략하여 완료 화면에서 오류가 발생했다. 저장된 답안은 모두 확인했고 시험 노드는 삭제/null 확인했다. v806은 빈 배치 재생·예약·응답·화면 정규화를 보완했다. 전체197/197·Functions17문법·실패0(110초), 새 RTDB 모형과 UI 완료/훼손 및 독립 감리를 통과했다.

공개 v806 최종 실서버 시험도 완료했다. 새 가명7명/비출전 임원21답안→빈 배치 정상 완료→공식 로컬 명부5명 저장·1명 유지/게스트1명 반영→8경기 생성·전원 점수 일치→저장·새로고침·복원 지문 일치. 두 번째 독립 프로필의 참가자는10문항을 받았고 자기 포함 질문0이었다. API22회 모두200·오류0·320/375/768/1024px 넘침0. 신규 시험 평가3건은 모두 삭제/null 확인, 임시 자격파일은 삭제했다. RSVP·명부 클라우드 쓰기·WebSocket·실제 외부 공유는 시험에서 차단했다. 명부 서버 저장은 실제 핸들러 회귀로 검증했으며 실계정 로그인 동기화 시험과는 구분한다.

실제 클럽 명부·신청 명단·진행 경기에 시험 쓰기는 하지 않았다. 실제 승률·물리 iPhone/iPad·실사용 임원 의견은 미검증이다.
