## 현재 구현

- 비회원은 그대로 명부·설정·대진·진행을 사용한다. Google 연결은 선택이며 원래 비회원 저장소와 백업을 보존한다. 회원 링크·이름 확인에는 Google 로그인을 요구하지 않는다.
- 같은 UID의 두 관리자 화면이 함께 열린다. 활성 화면은 5초 간격으로 최신 설정·경기를 조회하고, 로컬 설정 저장은 800ms 뒤 전송한다. 웹소켓 즉시 구독으로 표현하지 않는다.
- 명부의 서로 다른 회원/설정 항목은 경로별 비교로 병합한다. 같은 항목의 충돌은 원본과 내 값을 남겨 선택한다. 충돌 대기 중에도 무관한 항목은 저장된다. 다른 변경을 수신했다고 미해결 충돌을 자동 해소하지 않는다.
- 대진 생성·팀 구성 변경은 생성 당시 참가자/설정 전체를 비교한다. 그 사이 조건이 바뀌면 생성안을 백업하고 최신 조건에서 다시 준비한다. 다른 회원이 추가됐는데 옛 대진만 붙는 조합을 막는다. 명부 프로필 동기화 자체가 각 기기에서 팀을 다시 배정하지 않는다.
- UID + 탭 기기 번호별 캐시·설정 outbox·경기 outbox를 분리한다. 응답을 잃어도 같은 operationId로 재전송하며, 계정 전환 뒤 옛 응답을 다른 계정 화면에 적용하지 않는다.
- 경기는 UID의 비공개 연결에서 대상을 선택한다. 민턴LIVE는 기존 `applyCommandTransaction`/공식 경기 엔진, 팀전 결과는 기존 `applyTeamOfficialRequest`를 사용한다. 팀전의 나머지 관리자 수정은 최신 전체 상태 지문을 확인한 트랜잭션이며 충돌 시 재선택한다. 서로 다른 경기 결과는 각각 처리하고 같은 경기의 오래된 결과는 거절한다.
- 연결된 경기의 캐시는 일반 설정 패치로 덮어쓰지 않는다. 실제 Firebase compat SDK에서도 구식 직접 set/update/remove/push/transaction 경로를 차단한다. 일시정지·재개, 종료 취소·재종료, 링크 종료/기록 보관도 계정 명령으로 처리한다.
- 경기 종료 전 계정 비공개 보관함에 기록하고 공개 링크에는 명단을 남기지 않는다. 새 운동은 새 연결 ID를 사용한다. 기존 서버의 최근 완료 80경기 로그 제한 자체를 무제한 기록 보관으로 확장한 것은 아니다. 이미 기기에 있는 더 오래된 같은 운동 기록은 유지한다.

**자료 연결의 의미:** 기존 비회원 자료를 계정에 복사한다. 기존에 공유한 비회원 LIVE/팀전 링크의 소유권을 링크·이름만으로 가져오지 않는다. 진행 중인 비회원 사본을 가져올 때는 연결 화면에서, 원래 링크가 그대로 남고 계정 게시 시 새 링크가 생긴다고 알린다. 계정에서 만든 경기 링크는 두 기기가 동일하게 사용한다. 기존 실전 링크를 같은 URL로 계정에 이전하는 작업은 이 후보에 포함하지 않는다.
