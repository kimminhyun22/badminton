# 민턴LIVE 남은 일

## 결함 — 먼저 고친다 (2026-09-14 코덱스 수용 시험에서 발견, 클로드가 코드로 확인)
1. **권한 경계**: 선수 추가(`official-player-create`)가 요청의 `isClubOfficial:true` 를 그대로 저장한다(`functions/daily-official-engine.js` `applyPlayerCreate`). 클럽 임원·운영 도우미가 관리자 전용인 임원 자격 부여를 우회할 수 있다. 관리자 연결(`adminClaim`)일 때만 받도록 좁히고, 관리자 화면의 선수 추가가 이 필드를 쓰는지 확인한다. 서버 수정 → 래퍼 경로 테스트 → functions 배포 → 감리 요청.
2. **롤오버 화면 조건이 서버보다 좁다**: 서버는 4시간 넘은 미종료 코트를 접지만 임원 화면 `sessionRolloverEligible` 은 진행 코트가 하나라도 있으면 거절한다. 지난주 코트를 종료하지 않고 흩어지면 「종료」 상태 임원은 아무것도 못 한다. 화면 조건을 서버와 같게(4시간 안 된 코트만 막기) 맞추고, 롤오버 카드의 버튼 비활성 조건도 서버와 대조한다.
3. **롤오버 보관 저장을 확인하지 않는다**: 콜러블이 `liveArchive` 쓰기를 기다리지 않고 오류를 삼킨다(`functions/index.js` `submitDailyOfficialRequest`). 기다리고 실패를 기록한다.
4. **`liveArchive` 가 고아로 남는다**: 링크 종료는 `live/checkin_<ID>` 만 지우고, 청소 `cleanupExpiredLive` 는 남아 있는 `live` 노드만 순회한다. 청소가 `liveArchive` 도 훑게 한다(짝 없는 것·오래된 것).
5. **도착 명령 검증이 두 벌로 다르다**: 서버 `applyArrival` 은 `status` 없이도 적용하고 관리자 `_dailyOfficialRequestError` 는 거절한다. 실제 전송기는 `status:'wait'` 를 싣지만, 아래 「바로 해도 되는 것」 3의 구체 사례다.

## 운영자 확인이 필요한 것 (먼저 묻는다)
1. **회원 자가 도착** — 롤오버 뒤 회원이 본인 화면에서 도착을 누르게 할지. 「운영 흐름은 회원 입력에 의존하지 않는다」「늦게 오면 임원이 참가 등록」(DECISIONS 상시·2026-08-11)과 맞물려 보류 중.
2. **자동대진·운영 시간을 임원에게 열지** — 이를 위한 서버 명령이 없다(`official-settings-update` 는 코트 수만 받는다). 일시정지 **시작**은 2026-08-08 결정으로 관리자 화면에서도 없앴다(재개만 남음). 되살리는 것도 운영자 결정이다.
3. **디자인 브랜치 `codex/design-refresh`** — 2026-09-02 디자인 작업 2커밋. main 보다 30커밋 뒤처졌고(2026-09-14), 브리프가 병합 금지로 지정했다. 버릴지 다시 할지 결정 대기.
4. **성별 격차 1.5** — `gradeToLevel` 의 여성 −1 과 실효 −0.5 가 겹친다. 한 상수로 모으고 하한을 둘지(운영자: "우리 클럽 최저는 D조"). 팀전과 공용이라 영향이 크다.
5. **혼복의 「운동 후반」 조건** — 운영자 방침(2026-08-02)은 동성복식이 안 될 때와 운동 후반에만인데, 코드는 고정 문턱(`MIXED_PENALTY` 3,200)만 있다. 방침대로 구현할지, 지금 동작을 방침으로 확정할지.

## 바로 해도 되는 것 (권장 순서)
1. **임원 화면 일괄 도착 등록** — 롤오버 뒤 전원이 도착 전이라 임원이 한 명씩 참가를 누른다(20명이면 20번). 관리자 화면의 「전체 선택 → 현장 참가 등록」처럼 여러 명을 한 번에. 새 서버 명령이면 여섯 곳(PITFALLS 1)과 명령 크기 상한 24KiB를, 기존 명령을 여러 번 보내면 부분 실패 표시와 관리자 추종(리비전이 한 번에 여러 개 오른다)을 실배포로 확인한다.
2. **민턴LIVE 관리자 「임원 화면 열기」 버튼** — 팀전 관리자에는 있다(`liveConsoleTopBtn`). `js/daily.js` 에 `checkin.html?official=` 빌더는 있는데 여는 버튼이 없다. 팀전과 같은 자리·같은 문구로.
3. **관리자 재검사가 서버 적용분을 거절하면 영구 정지하는 구조** — 서버가 이미 적용한 명령은 관리자가 거절 대신 채택으로 넘어가게. 추종자의 핵심이라 감리 대상.
4. **상시 세션의 능력 표시 갱신** — 능력 표시는 관리자 게시로만 실린다. 관리자 없이 롤오버로 이어지는 세션에는 새 버튼이 영영 안 뜰 수 있다. 롤오버 때 서버가 표시를 갱신하는 길, 또는 배포 절차에 관리자 게시를 넣는다.
5. 일시정지 분류 차이 — 서버는 정지 중 23종을 막고 화면 두 벌은 13종만 막는다. 나머지 10종은 누르면 서버가 거절한다. 일시정지 시작이 없어져 우선순위는 낮다.
6. 보관 기록 보강 — 보관은 최근 80경기까지와 선수 id·이름·경기 수뿐이라 사후 감사가 일부만 된다. 급수·기대 경기 수를 함께 담을지.
7. `checkin.html` 에 12px 미만 글자 규칙이 50여 개 남아 있다. 폰 375px 렌더로 실제로 보이는 것만 정리한다.
8. 엔진 주석 가운데 지금 구현과 다른 것(코덱스 지적: 「9일」「48시간 연장」 등)을 정리한다.
9. 롤오버 직후 「새 링크가 필요합니다」 순간 표시(PITFALLS 11) — 재현되면 빈 스냅샷일 때 판정 보류.
10. PWA를 켜 둔 채 임원 연결(grant)이 만료되면 「다시 연결」을 손으로 눌러야 한다 — 자동 재연결.
11. 도착 전(planned) 상태 임원의 연결 해제 문구 다듬기.
12. 롤오버 되돌리기 — 지금은 게시 4시간·진행 코트 0·대기표 0·확인창으로만 막는다. 필요성 낮음.
