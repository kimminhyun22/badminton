# 민턴LIVE 감리 기록

역할: 코덱스 = 생산(만들고 배포). 클로드 = 감리(교차 모델 검토). 같은 모델은 자기 사각을 못 본다 — 검사기는 아는 결함만 센다.

## 언제 감리하나
- **필수**: functions 배포 / 새 명령 종류 / 관리자 추종·게시 경로 변경 / 실전 전날 배포.
- **정기**: 그 밖의 배포 5건당 1건(시작값).
- **완화**: 연속 3회 0건이면 10건당 1건, 연속 5회 0건이면 필수만. 결함이 다시 나오면 원래대로. 0건 감사도 기록한다 — 완화의 근거다.

## 약속
- 코덱스는 해당 작업을 마치면 아래 표에 「감리 요청」 줄을 남기고 다음 일을 계속한다. 감리를 기다리며 멈추지 않는다.
- 운영자가 클로드에게 넘기면, 클로드는 그 커밋 범위를 검토하고 결과를 같은 줄에 채운다.
- 지적은 기계로 잡을 수 있으면 테스트로 옮기고, 낡은 코드에서 그 테스트가 깨지는지 확인한다. 판단·취향이면 `DECISIONS.md` 나 `PITFALLS.md` 로 옮긴다.
