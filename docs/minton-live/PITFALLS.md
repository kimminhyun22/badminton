# 민턴LIVE 함정 목록

실측으로 확인된 결함 계열. 새 코드를 넣기 전에 해당 항목을 읽고, 막는 검사가 있으면 그 검사가 실제로 도는지 본다.

## 1. 새 임원 명령은 여섯 곳을 지나야 한다
- 증상: 서버는 적용했는데 관리자 화면 리비전이 멈추고 「서버 운영 기록 일부를 관리자 원본에 연결하지 못했습니다」 또는 「지원하지 않는 임원 운영 요청」.
- 목록: ① 엔진 `SUPPORTED_TYPES` ② 엔진 `applyByType`(되돌리기는 `applyUndo`) ③ 관리자 `_dailyOfficialRequestError` ④ 관리자 `dailyProcessCheckinRequests`(인라인 처리 또는 라우팅 배열) ⑤ 라우팅 배열에 올렸다면 `_dailyApplyAdminOperation` 분기 ⑥ 임원 화면 `sendOfficial*` 전송기 + 게시 페이로드의 능력 표시(`capabilities`).
- 사례: 2026-09-13 `official-operation-start` 가 라우팅 배열에서 빠짐 — 실배포 E2E가 잡았다.
- 그 밖에 볼 곳(검사가 대조하지 않는다): 관리자 중복 재생 판정 `_dailyServerOperationAlreadyApplied`, 재생 결과의 `preserveLocalQueue` 분류, 임원 화면 결과 표시 `officialRequestStateHtml`, 명령 크기 상한 `MAX_COMMAND_BYTES`(24KiB — 여러 명을 한 명령에 담을 때).
- 막는 검사: `tests/daily-command-lists-parity-regression.js` — 명령 목록 여섯 곳과 임원 화면 입구, 일시정지 분류의 화면 두 벌 일치(서버 `PAUSED_FLOW_TYPES` 의 부분집합)를 대조한다(훼손 시험 7종 확인). **문자열 대조라 능력 표시 누락·버튼 호출 단절은 못 잡는다** — 그 둘은 동작 테스트와 실배포 E2E로 본다.

## 2. 관리자 추종자가 서버를 조용히 되돌린다 (다섯 패턴)
관리자는 자기 로컬 상태로 게시본을 다시 만들어 올린다. 아래 중 하나만 있어도 서버에서 바뀐 것이 다음 게시에 사라진다.
1. **추론**: 명령 재생 중 「코트 등록 = 운영 시작」으로 넘겨짚어 게시 표시를 켰다(2026-09-13, `official-manual-match` 재생). 서버 사실만 따른다.
2. **보존 안 함**: 게시 페이로드에 없는 서버 소유 키(`archive`·`rolloverAt`·`rolloverCount`)를 게시마다 지웠다. 게시 트랜잭션에서 current 값을 옮긴다.
3. **축소**: 로컬 48시간 계산으로 서버가 30일로 늘린 만료를 줄였다. 서버 값보다 줄이지 않는다.
4. **조건부 덮기**: 「있으면 안 덮음」 헬퍼가 지난주 게시 시각을 남겼다. 채택은 서버 값을 무조건 받는다.
5. **정체 삭제**: 날짜가 바뀌면 로드 때 세션 정체(링크·초대·리비전)를 지워 다음 게시가 새 링크를 만들었다. 게시된 상시 세션은 날짜와 무관하게 보존한다(`_dailyCanResumeCrossDay`).
- 확인법: 「서버에 있는데 내 페이로드에 없는 키」「서버보다 짧아질 수 있는 값」「조건부로만 덮는 헬퍼」「날짜·시간으로 지우는 로드 로직」을 먼저 grep 한다. 통째 리셋은 재생이 아니라 채택으로 따른다.
- 막는 검사: `tests/daily-official-delegation-regression.js` 의 정적 핀. 최종 확인은 관리자 탭을 켠 실배포 E2E.

## 3. 행위자 상태 게이트는 네 곳이다
- 래퍼 `functions/daily-official-command.js`(`applyCommandTransaction`)와 엔진 `validateCommon` 이 각자 행위자 상태를 본다. 엔진만 고치면 래퍼에서 거절된다(2026-09-14 설계 검토에서 발견).
- 서버 밖에도 둘 더 있다: 클레임 `applyOfficialClaimTransaction` 과 임원 화면의 운영자/사전 세팅 판정이다. 새 예외는 네 곳을 함께 본다.
- 현재 예외: ① 운영 시작 전 `invited`·`planned` 정식 임원의 `official-roster-setup` ② 지난 운동의 종료 상태 정식 임원의 `official-session-rollover`. 첫 예외는 임시 도우미에게 열지 않는다.
- 막는 검사: `tests/daily-official-delegation-regression.js` 의 래퍼 경로와 `tests/daily-official-roster-setup-regression.js` 의 사전 클레임·명령 케이스.

## 3-1. 명부 일괄 설정은 요청 프로필을 믿지 않는다
- 화면은 선택한 `candidateKeys`와 상태만 보낸다. 이름·급수·성별·임원 자격은 서버의 `arrivalCandidates`에서 다시 읽는다.
- 후보 누락·다른 클럽·중복 키·100명 초과가 하나라도 있으면 전체 명령을 거절한다. 선수별 명령으로 쪼개 부분 성공을 남기지 않는다.
- 막는 검사: `tests/daily-official-roster-setup-regression.js` 의 프로필 위조·누락·타 클럽·중복·원자성 케이스.

## 4. 같은 검사가 두 벌이면 둘 다 고친다
- 서버와 관리자 재검사(`_dailyOfficialRequestError`)가 같은 규칙을 따로 가진다. 관리자 쪽이 더 좁으면 서버가 적용한 명령을 관리자가 거절하고, 그 뒤 모든 서버 결과가 관리자 화면에 안 들어온다(2026-08-04, 2026-08-09 실측).
- 구조 자체의 한계: 관리자 재검사가 서버 적용분을 거절하면 지금도 영구 정지한다 → `BACKLOG.md`.
- 시험할 때는 **실제 전송기**를 쓴다. 손으로 만든 페이로드는 필드가 빠져(예: 도착 명령의 `status:'wait'`) 관리자 재검사만 거절하는 가짜 결함을 만든다(2026-09-14).

## 5. 요청 페이로드의 예약 필드
- `type` 을 다른 뜻으로 싣지 않는다. 경기 종목을 `type:'자율'` 로 실었다가 명령 종류가 덮여 거절됐다(2026-09-13).

## 6. 게시 전에 명령을 보내면 서버가 모르는 경기가 된다
- 관리자 로컬에서만 시작한 경기의 종료 명령은 「종료할 진행중 경기를 찾지 못했습니다」(2026-08-04). `_dailySendAdminCommand` 는 보내기 전에 먼저 게시한다 — 플래그로 건너뛰지 않는다.

## 7. 지문을 빠뜨리면 거절된다
- 서버는 명령이 전제한 상태를 지문(`expectedPlayerIds`·`expectedStatus`·`expectedLastStatusAt` 등)으로 대조한다. 관리자 호출부가 지문을 안 실어 파트너 해제·게임신청 취소가 전부 실패했다(2026-08-04). 새 호출부는 기존 전송기의 지문 필드를 그대로 따른다.
- 토글 상태는 누르는 순간의 데이터에서 읽는다. HTML에 박으면 옛 값을 보내 동시성 검사에 걸린다.

## 8. 만든 것과 닿는 것은 다르다
- 같은 이름의 옛 함수가 파일 뒤쪽에 남아 새 함수를 덮어, 한 시간 동안 실행조차 안 됐다(2026-08-08). 검증 분기가 엉뚱한 함수 안에 있어 한 번도 불리지 않은 일도 있었다.
- 새 분기는 실제로 불리는지 호출해서 확인한다. 소스에 문자열이 있는지 보는 검사는 이 둘을 구별하지 못한다.
- 화면 조건이 서버보다 좁아도 같은 일이 생긴다: 서버는 4시간 넘은 미종료 코트를 접고 롤오버하지만, 임원 화면 `sessionRolloverEligible` 은 진행 코트가 하나라도 있으면 버튼을 막는다(2026-09-14 코덱스 수용 시험에서 발견, BACKLOG 결함 2).

## 9. 숨겨진 문구를 지우고 「정리했다」고 보고
- CSS(`display:none`)·단계 게이팅이 이미 감추던 문구를 중복이라 지웠다(2026-09-03). 화면은 하나도 안 바뀌었다. 보고 전에 배포본 스크린샷으로 확인한다.

## 10. 테스트 전제가 낡으면 「오탐」처럼 보인다
- 픽스처가 옛 사양(만료 10일)을 가정해 새 사양(30일)에서 틀린 결론을 냈다. 실패가 이상하면 기준부터 의심한다.
- 새 검사는 훼손 시험(고친 줄을 되돌리면 깨지는가)으로 검사한다. 통과는 증거가 아니다.

## 11. 롤오버 직후 잠깐 뜨는 「새 링크가 필요합니다」
- 관리자 게시 트랜잭션이 서버의 통째 트랜잭션과 겹치는 순간 빈 스냅샷을 소유권 불일치로 읽는 것으로 보인다. 다음 동기화에서 스스로 회복했다(2026-09-14 관측, 미수정). 재현되면 스냅샷이 비었을 때 판정을 보류하게 고친다.

## 12. 폰 화면
- font-weight 1000 은 로드된 글꼴(최대 900)에 없어 가짜 굵기로 글리프가 깨졌다(2026-08-16 실전). 900 상한, `text-size-adjust:100%`.
- 12px 하한은 기준 화면도 어긴다 — 팀전을 민턴LIVE에 맞춘 뒤 320px로 재 보니 민턴LIVE 쪽이 어기고 있었다(2026-09-13).

## 13. 대진 가중치
- 올릴수록 좋아지지 않았다(혼복 감점 4,500이 3,200보다 나빴다). 매번 중간값이 최적이었다. 회귀 테스트만 보지 말고 36명 시뮬로 종목·상대 반복·경기 수 min/max·성별 비중을 함께 본다(`MATCHMAKING_NOTES.md`).

## 14. 검사 결과를 파이프로 받으면 실패가 묻힌다
- `… test-all.js | tail -3 && git push` 는 `tail` 의 성공으로 판정되어, 이관 커밋이 94/95 상태로 푸시됐다(2026-09-14, README 문구가 팀전 테스트의 고정 구절을 지웠다). 검사 명령 자체의 종료 코드에 잇는다.

## 15. 배포와 캐시
- 정적은 푸시 후 1~3분. 폰은 서비스워커 캐시 때문에 새로고침·재실행 뒤 바뀐다. 이미 설치된 홈 아이콘은 매니페스트를 다시 받을 때까지 옛 시작 주소로 열릴 수 있다.
- 실기기 확인은 실제 배포로. 로컬 HTTPS 리그(인증서·서비스워커 경로)로 몇 시간을 버린 적이 있다(2026-08-04). 제품 문제가 아니었다.
