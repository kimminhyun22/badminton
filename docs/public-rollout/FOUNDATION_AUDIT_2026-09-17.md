# 콕매치 공개 배포 기반 감사

기준일: 2026-09-17

## 결론

현재 콕매치는 한 클럽의 현장 운영 도구로는 충분히 작동하지만, 루트 관리자 화면을 그대로 공개해 여러 클럽이 쓰게 하는 구조는 아니다. 공개화를 위해서는 기존 대진 로직을 다시 만드는 것이 아니라 **클럽별 저장 경계와 셀프 생성 입구**를 앞에 추가해야 한다.

## 현재 막히는 지점

1. 최초 클럽 명부와 상시 링크를 시스템 관리자 브라우저에서 만든다.
2. 민턴LIVE 관리자 원본 일부가 해당 브라우저 localStorage에 있어 다른 기기 복구가 어렵다.
3. 민턴LIVE와 팀전LIVE의 세션·명부 수명이 달라 같은 참가자를 반복 입력할 수 있다.
4. 회원 링크는 간단하지만, 새 클럽 생성자와 운영 권한을 안전하게 증명하는 셀프서비스 경로가 없다.
5. 공개 생성 시 클럽 간 데이터 격리, 생성 남용, 자동 삭제와 비용 상한을 보장하는 계약이 없다.
6. 민턴LIVE 백로그의 롤오버·보관 결함 2~5는 공개 파일럿 전에 해소해야 한다.

## 목표 구조

### 클럽 공간

- `clubId`: 클럽의 영구 경계. 명부·임원·기본 코트·운동 기록이 이 아래에만 존재한다.
- `eventId`: 한 번의 자유운동 또는 팀전. 종료 후에도 클럽에 속한다.
- 생성자는 자동으로 클럽 대표가 되며, 중앙 관리자의 승인을 기다리지 않는다.
- 대표·임원은 같은 회원 링크에서 운영하며 별도 임원 링크를 배포하지 않는다.

### 링크

- 회원에게는 클럽별 영구 링크 하나만 배포한다.
- 링크는 현재 열린 운동을 자동으로 보여 주고, 없으면 `오늘 운동 준비 중`만 표시한다.
- 운영자는 같은 링크에서 기기 자격 또는 운영 복구 수단을 확인한 뒤 운영 도구를 사용한다.
- 이벤트마다 새 카카오톡 링크를 만들지 않는다.

### 명부

- 클럽 명부는 민턴LIVE와 팀전LIVE가 함께 사용한다.
- 이름·성별·급수·임원 여부만 기본으로 저장하며 불필요한 개인정보를 요구하지 않는다.
- 오늘 참가자만 이벤트에 복사하고, 원본 명부 수정과 당일 상태 변경을 구분한다.

### 권한

- 중앙 시스템 관리자: 장애·남용·비용과 예외 복구만 담당한다.
- 클럽 대표: 클럽 삭제·복구·임원 지정과 전체 운영.
- 클럽 임원: 명부 선택, 운동 생성, 대진·코트·선수 상태 운영.
- 운영 도우미: 해당 이벤트의 현장 진행만 지원하고 종료 시 자동 해제.
- 회원: 가입 없이 본인 경기와 진행 상태 확인. 운영 권한은 이름 선택만으로 얻지 못한다.

## 전환 원칙

1. 기존 `index.html`, `team.html`, 상시 회원 링크는 파일럿이 끝날 때까지 유지한다.
2. 새 클럽 공간은 별도 데이터 경계에서 시작하고 기존 실전 세션을 자동 변환하지 않는다.
3. 대진 알고리즘과 현장 UI는 재사용하되, 저장·권한 원본을 서버 클럽 공간으로 옮긴다.
4. 클럽 생성·복구·삭제는 중복 재시도에도 같은 결과가 남도록 operation ID를 쓴다.
5. 공개 파일럿 전에 App Check, 요청 제한, 만료·삭제, 타 클럽 접근 회귀를 통과한다.
6. 현재 동결된 `database.rules.json`은 별도 승인과 백업·diff·에뮬레이터 검증 없이 수정하거나 배포하지 않는다.

## 첫 구현 단위

1. 두 합성 클럽과 대표·임원·회원 픽스처를 만든다.
2. 클럽 A 자격으로 클럽 B 명부·이벤트를 읽기/쓰기 할 수 없는 서버 계약을 테스트한다.
3. `createClub` 입력·결과·중복 방지·삭제·복구 계약을 고정한다.
4. 서버 경계가 통과한 뒤에만 `우리 클럽 만들기` 화면을 연결한다.

## 공개 파일럿 전 필수 확인

- 새 기기에서 대표 권한 복구
- 대표 두 명 또는 임원 여러 명의 동시 조작
- 같은 이름 회원 구분
- 클럽 삭제 후 명부·세션·보관 기록 잔존 여부
- 만료된 이벤트와 고아 보관 기록 정리
- 요청 폭주·반복 생성 제한
- Firebase 비용과 오류 알림
